Origin Story & Core Philosophy

The Support Origin Narrative

Why spending 1.5+ years on the receiving end of software failure makes me an obsessively user-first developer.

"On a support line you learn fast that the user isn't confused — the product is."

PRINCIPLE RECORDED DURING TECHNICAL SUPPORT & HELP DESK TENURES

"I spent a year and a half answering calls from people whose software had just failed them, then carried that instinct into help desk and infrastructure work. When the same switch configuration had to be typed by hand across dozens of devices, I wrote a generator instead. Find the friction, remove it. Somewhere in there I stopped wanting to fix other people's software and started building my own."

01

Zero-Friction Flows

Every extra click, ambiguous label, or loading stall is an invisible failure point. I design mobile interfaces that respect user attention and time.

02

Defensive Coding

Users will lose connectivity, input corrupt formats, and click buttons twice. I build robust error boundaries and offline-first state handling by default.

03

Automation Instinct

If an action has to be done twice, generate a script. Whether it's Cisco VLAN switch CLI or batch data mapping, manual repetition is technical debt.

04

Network Awareness

With CCNA certification, I understand TCP/IP, latency budgets, packet loss, and firewalls at Layer 2 & 3 — making my mobile REST API calls resilient.
